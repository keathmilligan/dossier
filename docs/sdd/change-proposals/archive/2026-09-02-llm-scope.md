# Judge pages with a policy prompt

| Created | Updated |
| --- | --- |
| 2026-08-24 | 2026-09-02 |

## Why

Include/exclude keywords are brittle. The user already has an LLM on the box. A short prompt that describes the topic is easier to write and closer to what they mean.

## What changes

- **Policy is a prompt.** The Policy tab is one textarea. Edits apply immediately (`PUT /topics/:id/policy` with `{ prompt }`). Creating a topic still inserts an empty policy so Sites works. An empty prompt captures nothing.
- **No keyword match.** Delete include/exclude lists, the chip UI, `keywordHits` / `matchesPolicy` / `normalizeTerms`, and `include_json` / `exclude_json`.
- **Every watched page is sent.** A page on a topic's site list (denylist, incognito, length, and pause unchanged) is stored and shown as **Queued**. The service asks the LLM whether the page is in scope given the prompt. Accept → `filed`. Reject → `rejected`.
- **Filings show Queued.** Default list is queued + filed, newest first. Rejected stay hidden unless asked. Manual reject still works on queued or filed. No keep/refile.
- **LLM down stays queued.** The judge retries; it does not drop or auto-file.
- **Prompt edits do not re-judge.** Already queued, filed, or rejected rows stay as they are. New pages use the current prompt.
- **Assist topic pick** no longer scores include terms. Retrieve stays keyword/FTS over captured items.
- **No compatibility.** Bump schema. Replace `dossier.sqlite` on version mismatch.

## Scope

- In: policy model and API (single prompt string); ingest of all watched pages; queued filing state; LLM scope judge and retry; Policy textarea; delete keyword matching and its tests/docs
- Out: re-judging on prompt change; embeddings; outline, inbox, pin, chat, brief; changing assist draft behavior; changing sites, pause, or the side panel

## Impacted specifications

- `ui` (existing) — Policy tab becomes a textarea; Filings show Queued
- `policy` (existing) — prompt instead of term lists
- `capture` (existing) — queue then judge, not match-at-ingest

## Open questions

- None if the defaults above are accepted. Say if an empty prompt should queue everything, or if a prompt edit should re-open queued rows.
